# Bookplate

把實體書的照片轉成有結構的電子書。中英文 OCR、跨頁段落自動縫合、標題層級還原、封面與版權頁自動建檔，輸出 Markdown / EPUB / Word / PDF，並可生成 AI 摘要。

自用工具，跑在本機。API key 只留在 Node 端，不會進入前端 bundle。

---

## 快速開始

```bash
git clone <你的 repo 網址>
cd bookplate
npm install

cp .env.example .env        # Windows: copy .env.example .env
# 編輯 .env，填入 https://console.anthropic.com/settings/keys 取得的金鑰

npm run dev                 # http://localhost:5173
```

需要 Node 18 以上。

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發伺服器，含 Anthropic 代理 |
| `npm run build` | 型別檢查 + 打包到 `dist/` |
| `npm run preview` | 預覽打包結果（注意：不含 API 代理） |
| `npm run test` | 核心邏輯的煙霧測試（縫合、Markdown、JSON 救援） |
| `npm run typecheck` | 只跑 TypeScript |

## 使用流程

**1. 放照片。** 拖曳、貼上、或選檔，一次最多 25 頁。頁序就是輸出順序，可以拖曳卡片調整。

拍攝建議：光線平均、書頁盡量壓平、單頁入鏡。一次拍攤開的兩頁也可以 —— 系統會偵測出橫式照片並提示「拆成兩頁」，拆開後辨識率和段落判斷都會更好。

**把封面和版權頁一起拍進去。** 系統會自動認出它們，抓出書名、副標、作者、譯者、出版社、年份、版次與 ISBN，填進成品的書目資料；同時這些頁面的文字不會混進正文。

**2. 辨識設定（選用）。** 左欄的「辨識設定」裡有四個旋鈕：

- **書的文字** — 指定繁體／簡體／英文後，不會發生繁簡互轉。
- **專有名詞** — 一行一個。人名地名容易每頁寫法不同，先寫在這裡，全書就會一致。這是提升品質最有效的一個欄位。
- **強化對比** — 轉灰階並拉對比。泛黃紙張或光線不足時才開，之後匯入的照片才會套用。
- **辨識封面與版權頁** — 預設開啟。詳見下一節。
- **自動修正標題層級** — 只拍了中間幾章、全書沒有第一層標題時，把第二層提升上來，目錄才不會整層空掉。

**3. 掃描。** 三頁同時處理，逐頁顯示進度、耗時與 token 用量。單頁失敗可以重試，不影響其他頁。

掃描完成後每一列右側有角色下拉選單（封面／書名頁／版權頁／目錄／內文／空白）。模型判斷錯了在這裡改，手動指定一律優先。

**4. 校對與匯出。** 右欄有「出版資訊」與五種匯出格式。所有書目欄位都可以手動修改，改過的值優先於辨識結果。「編輯原文」可以直接改 Markdown —— OCR 不會百分之百正確，專有名詞和數字值得再看一眼。

## 封面與版權頁

這個功能不只是「多抓幾個欄位」，它同時解決兩件事。

**一、把出版資訊建成結構化書目。** 每一頁辨識時會順便判定它在書裡的角色，是封面、書名頁、版權頁、目錄、內文還是空白。判定為前三者的頁面會額外抽出書目欄位。這是**同一次 API 呼叫**完成的，不額外花錢也不增加延遲。

**二、把這些文字擋在正文外。** 這才是真正的痛點。沒有角色判定的話，「ISBN 978-…」「初版一刷」「版權所有 翻印必究」會直接出現在第一章開頭。現在只有內文與目錄會併進書稿。

多張前置頁的資訊會合併，欄位優先序不是隨便定的：

| 欄位 | 優先來源 | 理由 |
|---|---|---|
| 書名、副標、作者、譯者、叢書、原文書名 | 書名頁 → 封面 → 版權頁 | 封面常省略副標與譯者 |
| 出版社、年份、版次、ISBN | 版權頁 → 書名頁 → 封面 | 版權頁才是權威來源，封面印的常是舊資訊 |

其他處理：民國年由模型換算成西元（民國 X 年 + 1911）；ISBN 去除連字號並驗長度；作者欄剝除「作者：」「著」「譯」這類標籤；沒印在頁面上的欄位一律留空 —— prompt 明確禁止模型憑記憶補書名或年份。

書目資料的去向：

- **Markdown** — YAML front matter，直接被 Obsidian、Zotero 讀取
- **EPUB** — `dc:title` / `dc:creator` / `dc:contributor` / `dc:publisher` / `dc:date`，有 ISBN 時用 `urn:isbn:` 當識別碼，並自動生成書名頁
- **Word / PDF** — 書名頁印出書名、副標、作者譯者、原書名與版權單行

## 架構

```
image → normalize → OCR (vision) → stitch → markdown → render / export
                                      ↑
                              純邏輯，不呼叫 API
```

**`src/lib/image.ts`** — 縮到長邊 1568px 再送出。這是 vision token 的甜蜜點，再大不會提升辨識率，但成本和延遲會線性上升。跨頁切分、旋轉、對比強化也在這裡。

**`src/lib/ocr.ts`** — 單頁辨識。要求模型回傳嚴格 JSON，包含 `starts_mid_sentence` / `ends_mid_sentence` 兩個旗標。解析有三層防禦：剝除 markdown fence → 切出首尾大括號 → 正則從被截斷的回應裡撈出完整區塊。

**`src/lib/metadata.ts`** — 頁面角色判定與書目合併。`isBodyPage()` 決定哪些頁進正文，`mergeMetadata()` 處理跨頁欄位優先序，正規化負責年份、ISBN 與姓名標籤。

**`src/lib/stitch.ts`** — 跨頁縫合，**刻意不用 LLM**。前一頁句子沒結束 + 這一頁從半句開始 → 接回同一段；中文邊界不補空格，英文補一個。純邏輯的好處是零成本、零延遲、結果可重現。同一份輸入永遠得到同一份輸出。

這裡也處理頁眉去除，規則刻意保守：只看每頁首尾區塊、只處理 caption 與 p、長度 30 字以內、兩頁以上重複。標題型別一律不動 —— 很多書每章都有「本章摘要」這種同名小節，誤刪真標題的代價遠高於留下幾行頁眉。

**`src/lib/exporters.ts` / `epub.ts`** — 四種輸出各有取捨：

| 格式 | 做法 | 為什麼 |
|---|---|---|
| `.md` | 直接輸出，含 front matter | 無爭議 |
| `.epub` | JSZip 組 EPUB 3，依 h1 切章 | 唯一能在閱讀器重新排版的格式 |
| `.doc` | HTML + MSO namespace + UTF-8 BOM | 不走 docx 產生器，中文字型不需嵌入，Word 用系統字型渲染不會缺字，且完全可續編 |
| `.pdf` | 隱藏 iframe 呼叫系統列印 | 排版交給 OS 字型，中文不會缺字。沙箱擋列印時可改用「列印版網頁」 |

**`src/lib/draft.ts`** — IndexedDB 自動存檔。重點不是怕重整，是**已經付費跑完的 OCR 不該重跑一次**。下次開啟會問要不要接續。

**`src/lib/summarise.ts`** — 三種模式。文稿超過 12000 字自動切換成 map-reduce（先逐段做筆記，再整合）。

## 調校

所有旋鈕集中在 `src/config.ts`：

```ts
OCR_MAX_TOKENS = 8000   // 中文滿版書頁約需 2000–4000，8000 留足餘裕
MAX_PAGES = 25          // 自用可調高，併發與記憶體會跟著上升
POOL = 3                // 同時進行的請求數，太高容易撞 rate limit
MAX_EDGE = 1568         // 影像長邊上限
USD_PER_MTOK_IN/OUT     // 用來估算花費，價格會變動請自行更新
```

介面上顯示的花費是用上面兩個常數乘 token 數估的，只能當量級參考。

## 部署（選用）

`api/anthropic.ts` 是為 Vercel 準備的 serverless function，本機開發用不到。

```bash
npx vercel
# 在 Vercel 專案設定加上環境變數 ANTHROPIC_API_KEY
```

**部署到公開網址前請先加上存取控制。** 沒有任何驗證的話，任何知道網址的人都能用你的 API 額度。最省事的做法是開 Vercel 的密碼保護，或在 function 開頭檢查一個共享密鑰。

## 已知限制

- **HEIC 讀不了。** iPhone 預設格式，瀏覽器不支援。先在手機設定裡改成「相容性最佳」，或匯出時轉 JPG。
- **直排書、注音、複雜表格辨識效果不穩。** 這類版面超出目前 prompt 的設計範圍。
- **封面判定偶爾會誤判。** 全頁大圖的章名頁可能被當成封面，設計感強的封面也可能被當成內文。掃描完在角色下拉選單改，手動指定一律優先。
- **書目資料只抄頁面上印的。** 不會去查資料庫補齊。版權頁沒拍到，就只會有封面上的那幾欄。
- **辨識不是百分之百正確。** 專有名詞、數字、年份最容易出錯，匯出前用「編輯原文」看過一遍。
- **`npm run preview` 沒有 API 代理。** 那是純靜態預覽，要測辨識請用 `npm run dev`。
- **每次只處理一批。** 沒有跨批次的書籍管理，第二批要重新開始。
